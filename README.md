# Retail Ops Assistant

Локальная программа для специалиста по товарным данным и маркировке: собирает поставки из CSV/Excel, находит ошибки, сверяет данные с загруженным эталоном, готовит черновики и переименовывает копии фотографий.

**Статус: рабочая первая версия для выгрузок. Прямые интеграции с 1С, ИС МПТ и НКТ пока не реализованы.** Проект создан по описанию обязанностей в розничной торговле. Он не является официальным продуктом INTERTOP и не использует внутренние данные компании.

## Быстрый запуск

Нужен Python **3.11 или новее**. В папке проекта:

```bash
python -m retail_ops
```

Откроется `http://127.0.0.1:8765`. CSV, фотографии и расчёт времени работают без сторонних библиотек. Для чтения Excel один раз установите дополнение:

```bash
python -m pip install ".[excel]"
```

На Windows вместо `python` может понадобиться `py -3`. Для запуска также есть `start_windows.bat`. На macOS используйте `python3 -m retail_ops` или `sh start_macos.command`.

1. Нажмите **«Проверить на примере»**. В примере 8 товарных строк, 3 проходят как черновики, 5 заблокированы.
2. Просмотрите ошибки, товары, сводку поставок и сверку количества КМ.
3. Скачайте ZIP с отчётами.
4. Скачайте примеры CSV, замените синтетические строки своими и проверьте файлы.

Данные в примерах вымышлены. GTIN приведены для проверки алгоритма; их принадлежность товарам не заявляется. `DEMO-NTIN-*`, `DEMO-KM-*` и `example.com` — условные демонстрационные значения, не реальные идентификаторы и не источник сведений бренда.

## Что работает

| Обязанность | Реализация в версии 0.1 |
| --- | --- |
| Консолидация данных | Несколько CSV/XLSX в один набор; у каждой строки сохраняются файл и номер строки |
| Проверка полноты | Обязательные поля, положительное целое количество, настраиваемое требование NTIN |
| Контроль GTIN | Длина, ASCII-цифры, контрольная цифра GS1, конфликты между вариантами товара |
| Поиск дублей | Вариант определяется по бренду, точному артикулу, цвету и размеру; повторы внутри поставки блокируются |
| Проверка сведений бренда | Сверка с вручную проверенным эталоном, содержащим URL и дату; расхождения показаны отдельно |
| Подготовка карточек | Черновики строк без блокирующих ошибок в общем формате |
| Подготовка заказа КМ | Суммы количества по поставке и GTIN только для прошедших проверку строк; статус `draft` |
| Контроль полученных КМ | Сравнение количества по поставке/GTIN, дубли, недостаток, избыток, коды без поставки |
| Фото | ZIP + таблица соответствий → ZIP копий с новыми именами и журналом SHA-256 |
| Оценка эффекта | Калькулятор с изменяемыми минутами и долей автоматизации по каждой операции |

### Границы проверки

- Контрольная цифра GTIN не подтверждает регистрацию или право использования. Программа **не присваивает GTIN**.
- NTIN сохраняется как текст. Правила выдачи и действительность в НКТ здесь не проверяются; алгоритм GS1 к NTIN не применяется.
- КМ сохраняются как точные строки, включая ASCII GS и пробелы. Программа не заказывает КМ, не проверяет криптографию, привязку к товару и статус в ИС МПТ.
- Статус совпадения количества КМ означает только числовую сверку. Он не подтверждает пригодность или подлинность кодов.
- Отсутствие эталона или совпадения в нём вызывает предупреждение. `draft_ready` означает только отсутствие блокирующих ошибок по локальным правилам. Перед передачей нужно проверить предупреждения.
- Официальность и свежесть эталона подтверждает сотрудник. Сайт бренда автоматически не посещается.
- Общие CSV — **не готовый официальный импорт** в 1С/ИС МПТ. Под реальный шаблон нужно согласовать колонки, единицы и обязательные атрибуты. Смысл «ШНС» не предполагается: это настраиваемое сопоставление поля заказа.
- Нет автопополнения счёта, отправки документов или подписи ЭЦП. Нет рабочего мониторинга баланса.
- Поддерживается до 30 000 строк поставок суммарно, 20 файлов, 15 МБ на файл и 32 МБ на HTTP-запрос с учётом Base64. Распакованный архив — до 80 МБ и 5000 записей. Для больших объёмов нужен потоковый импорт и нагрузочное тестирование.
- XLSX должен содержать один лист. Числовые ячейки идентификаторов и формулы блокируются: восстановить уже потерянные ведущие нули автоматически нельзя. Формат `.xls` не поддерживается.

## Входные таблицы

CSV: UTF-8 (в том числе с BOM) или Windows-1251, разделитель `;`, `,` или табуляция. Заголовки в первой строке. Рекомендуется UTF-8 с `;`. Идентификаторы хранятся строками. Пробелы по краям обычных идентификаторов убираются; содержимое КМ сохраняется целиком.

| Поле | Русский заголовок | Обязательность |
| --- | --- | --- |
| `shipment_id` | Поставка / Номер поставки / Заказ | Да |
| `supplier` | Поставщик | Да |
| `sku` | Артикул | Да |
| `brand` | Бренд | Да |
| `name` | Наименование | Да |
| `color` | Цвет | Да |
| `size` | Размер | Да |
| `quantity` | Количество | Да, целое положительное число |
| `gtin` | GTIN / Штрихкод | Да |
| `ntin` | NTIN | По настройке; иначе отсутствие — предупреждение |
| `material`, `country` | Материал, Страна | Необязательные для общего черновика |

Для сверки эталона: `sku`, `brand`, `color`, `size`, `source_url`, `checked_at` и проверяемые поля `name`, `gtin`, `ntin`, `material`, `country`. Соответствие ищется по бренду + точному артикулу + цвету + размеру. Неоднозначное соответствие не используется. Регистр и повторные пробелы в описаниях не учитываются; артикулы не приводятся к одному регистру.

Для сверки КМ: `shipment_id`, `gtin`, `km`. Все вхождения повторного КМ исключаются из счётчика до проверки. GTIN-8/12/13 нормализуются к 14 знакам **только для сравнения**; исходный товарный GTIN остаётся в отчёте.

Для фото: `original_name`, `sku`, `color`, `size`, `view`. Пример: `photo01.jpg;SN-001;black;42;front`. Выходное имя: `SN-001/SN-001_black_42_front.jpg`. Допустимы буквы, цифры, `_` и `-`. Конфликты имён, повторные исходники и опасные пути останавливают операцию. Изображения не меняются и не проверяются на размер, качество или соответствие товару.

Своё сопоставление названий столбцов можно вставить в интерфейсе или передать через CLI. Пример — `config/column_mapping.example.json`.

| Файл | Содержимое |
| --- | --- |
| `products.csv` | Все исходные строки после нормализации, источник и статус |
| `issues.csv` | Ошибки и предупреждения с номером исходной строки |

| `shipments.csv` | Сводка поставок, известное количество и строки с ошибками |
| `reference_comparison.csv` | Значения из поставки и эталона, ссылка и дата источника |
| `km_request_drafts.csv` | Общие черновики количества КМ по поставке и GTIN |
| `km_reconciliation.csv` | Проверка количества уже полученных КМ |
| `result.json` | Полные данные отчёта и SHA-256 файлов и нормализованных входных наборов |
| `READ_ME.txt` | Условия использования результатов |

CSV открывайте в Excel через **Данные → Из текста/CSV** с типом «Текст» для идентификаторов. Обычное открытие двойным щелчком может убрать ведущие нули. Значения с формульным префиксом в CSV защищены апострофом; строки до этой защиты доступны в JSON. Удалённые из входных данных сведения восстановить невозможно.

## Командная строка

```bash
python -m retail_ops demo
python -m retail_ops check supplier1.csv supplier2.csv --reference brand.csv --codes km.csv --output outputs/check-001.zip
python -m retail_ops check supplier.csv --require-ntin --mapping config/column_mapping.example.json --output outputs/check-002.zip
python -m retail_ops serve --port 8766 --no-browser
python -m unittest discover -s tests -v
```

CLI не перезаписывает существующий отчёт: для следующего запуска задайте другое имя. Для Python `3.11–3.13` настроен GitHub Actions. Локальная проверка в данной среде и запуск CI в GitHub — отдельные проверки; наличие workflow не означает, что он уже выполнялся в вашем аккаунте.

## Данные и доступ

Обработка происходит локально. Во время обработки программа не обращается к внешним сайтам, облачным сервисам, ИИ, 1С или порталам. Веб-интерфейс слушает только `127.0.0.1`, проверяет Host, Origin и случайный токен запросов. Загруженные данные не пишутся сервером на диск; скачанный пользователем отчёт сохраняется обычным способом браузера. Это однопользовательский инструмент, не корпоративный сервер. На общедоступном сервере развёртывать его без дополнительной защиты нельзя.

В репозиторий входят только код и синтетические примеры. Рабочие выгрузки храните в `data/`, результаты — в `outputs/`: эти папки исключены через `.gitignore`. Это не механизм предотвращения утечки: перед коммитом отдельно проверяйте состав файлов. Пароли, токены, ключи ЭЦП, настоящие КМ и данные поставщиков в GitHub не загружайте.
